# UI/UX Skill

## Purpose

Design interfaces that are clear, coherent, usable, responsive, and visually intentional.

This skill governs interface design decisions rather than merely CSS implementation.

The objective is to make the interface understandable and pleasant to use while preserving the application's actual functionality.

---

## When to Use

Use this skill when:

- Designing a new interface
- Creating a landing page
- Building dashboards
- Redesigning existing UI
- Creating navigation
- Designing forms
- Creating cards, modals, dialogs, or tables
- Choosing typography or spacing
- Improving visual hierarchy
- Creating responsive layouts
- Implementing animations

---

## Core Principles

Prioritize:

1. Clarity
2. Usability
3. Consistency
4. Accessibility
5. Responsiveness
6. Visual hierarchy
7. Performance

Visual complexity should not exist without a purpose.

---

## Before Designing

Inspect:

- Existing design system
- Colors
- Typography
- Spacing
- Components
- Icons
- Existing pages
- Responsive patterns
- Interaction patterns

If the project already has a design system, extend it instead of creating a competing system.

---

## Visual Hierarchy

Important information should be visually distinguishable.

Use:

- Typography
- Size
- Weight
- Spacing
- Alignment
- Grouping
- Contrast
- Position

Avoid making everything visually prominent.

Users should quickly understand:

- Where they are
- What the page is about
- What they can do
- What action is most important
- What happened after an action

---

## Layout

Prefer deliberate layout systems.

Use appropriate:

- Grid
- Flexbox
- Containers
- Spacing scales
- Alignment rules
- Responsive breakpoints

Avoid arbitrary pixel positioning unless genuinely necessary.

Do not create layouts that depend on a single viewport size.

---

## Forms

Forms should clearly communicate:

- Field labels
- Required fields
- Input expectations
- Validation errors
- Submission state
- Success state
- Failure state

Do not rely exclusively on placeholder text as a label.

---

## Feedback

User actions should have appropriate feedback.

Examples:

- Loading indicators
- Disabled states
- Success messages
- Error messages
- Empty states
- Progress indicators
- Confirmation for destructive actions

Avoid unnecessary notifications.

---

## Navigation

Navigation should be predictable.

Ensure:

- Current location is understandable.
- Important destinations are discoverable.
- Mobile navigation remains usable.
- Back/navigation behavior is sensible.
- Deep links work when applicable.

---

## Animation

Animations should communicate state, hierarchy, or spatial relationships.

Use animation carefully for:

- Enter/exit
- Loading
- State changes
- Navigation
- Feedback
- Focus

Avoid:

- Excessive animation
- Distracting effects
- Long delays
- Animation that blocks interaction

Respect reduced-motion preferences.

---

## Visual Consistency

Maintain consistency in:

- Buttons
- Inputs
- Cards
- Headings
- Icons
- Spacing
- Border radius
- Shadows
- States
- Interaction patterns

Do not introduce one-off styles when an existing pattern already solves the problem.

---

## Design Quality Check

Before completion, ask:

- Is the purpose immediately understandable?
- Is the hierarchy clear?
- Are important actions obvious?
- Are states represented?
- Does the layout work on small screens?
- Is text readable?
- Are interactions predictable?
- Does the design match the rest of the application?
- Does the interface remain usable without animations?

---

## Verification

When browser or screenshot tools are available, inspect the actual rendered interface.

Check:

- Layout
- Overflow
- Spacing
- Typography
- Responsive behavior
- Interaction states
- Visual regressions

Do not assume that correct CSS guarantees correct visual output.

---

## Completion Criteria

A UI/UX task is complete when the requested interface works functionally and the resulting design is coherent, usable, responsive, accessible, and consistent with the project's visual language.
